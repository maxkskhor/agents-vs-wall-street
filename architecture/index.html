Agents vs Wall Street

Glasshouse

A forecasting agent built on one rule: the language model is never allowed to say a forecast number. Models transcribe cited evidence and propose assumptions; deterministic arithmetic computes all twelve figures; a time-travel backtest — not taste — chooses how the estimates are combined.

Agent name: Glasshouse

Team: Team MYS — Max Khor, Yash Rai, Swareena Gurung

Build style and harness: A constrained-role pipeline, not an agent loop — no planner, no autonomous tool use, no multi-agent debate. The program calls models only for bounded, single-document jobs; all composition and arithmetic is ordinary code, and model output that fails a gate is discarded rather than negotiated with.

Models: One cheap OpenAI model in every role — transcription, analyst, red-team and consensus search. We tested a stronger model in the analyst role against the backtest and it scored worse, so it is not used. Exact model IDs are recorded in the entry form.

How it works

One command — .venv/bin/python -m agent run --all — runs the four companies in parallel through the same five stages, finishing in about 25 seconds. Every stage writes a JSON artifact under runs/<run-id>/, so each submitted cell can be traced offline from evidence to number.

The five stages

  1. Retrieve. Deterministic selection from the frozen corpus: the newest results-flavoured filings (8-Ks, trading updates, annual/quarterly reports) per company, ordered by date. No embeddings — filenames and frontmatter already carry date, type and period, and rg covers targeted search.
  2. Extract. An LLM transcribes, one document at a time: reported values, prior-year comparatives, guidance ranges and pre-announcements for the three challenge metrics — each with a verbatim quote. A fact survives only if the quote exists in the document and the number appears in the quote (unit-aware: $41.8bn ≈ 41,765 USDm). Everything else is logged as rejected.
  3. Estimate — three independent routes.
    • Guidance-anchored: pure arithmetic on extracted guidance — midpoints, full-year "catch-up" math (implied remaining-quarter growth given already-reported quarters), historical seasonal shares.
    • Statistical: prior-year base × median YoY growth (additive in points for percent metrics). Contains no model call at all.
    • LLM analyst: five to eight independent samples, run in parallel. The model must pick a base figure from the supplied history table and propose itemised, cited adjustments; the engine recomputes base + Σdeltas and rejects any sample whose base is not a real historical value.
  4. Combine. Weighted median across routes — weights chosen by the backtest, not by us — then an optional shrink toward the live public consensus anchor: final = consensus + β·(ensemble − consensus), β = 0.6.
  5. Validate, then write. Deterministic gates (units and magnitudes vs history, cross-metric consistency such as HD comp-sales vs net-sales growth and Hays fee-to-profit conversion, cross-provider disagreement) plus an LLM red-team pass that can block only on unit/scale errors. Any failure stops the workbook writer.

Research and financial reasoning

The scoring rule shaped the design. Accuracy is judged relative to Wall Street: |our miss| / max(WS miss, floor), capped at 5.0. Three consequences:

  • All four fiscal periods have already ended. We are predicting reported numbers for completed periods, so the freshest signals dominate: the latest guidance, and pre-announcements. Hays' 10 July trading update effectively pre-announces FY2026 net fees — the extractor treats it as a first-class pre-announcement fact that outranks older guidance.
  • Median beats mean. Under absolute-error scoring the optimal point forecast is the median of our belief distribution — hence weighted medians, never averages, everywhere in the engine.
  • Consensus is the benchmark, so know where it is. A cited, timestamped snapshot of public consensus (fetched by the models' web-search tools, cached to research/) anchors the final number; the ensemble moves us away from consensus only where extracted evidence pushes. If the network fails, the run proceeds un-anchored — the anchor is an input, not a dependency.

Conflicting evidence is resolved structurally rather than by vibes: later documents win for restatements; pre-announcements outrank guidance; adjusted-basis quotes are required for adjusted metrics; and quarterly figures are reconciled against full-year guidance through the catch-up arithmetic.

What the backtest measured

The corpus is frozen and dated, so the same pipeline can run "as of" the day before each past earnings report and be scored against the actual that later filings reveal. We report the floor-relative miss (our miss ÷ scoring floor, capped at 5.0) — the score we would receive if Wall Street were perfect, an upper bound on the real score.

We backtested 59 metric-level forecasts across the four companies — every reporting event since mid-2024 that the corpus can score. Mean floor-relative miss per route:

RoutenMean floor-relative missReading
LLM analyst593.55Always available; best overall, and best on percent metrics
Guidance arithmetic303.71Strong where it applies; abstains on 29/59 (Deere gives no usable quarterly guidance)
Statistical (no LLM)524.39Honest baseline, and the only route that survives on Hays EPS

We also used the backtest to settle a question we would otherwise have guessed at: is a bigger model a better analyst? Running the identical backtest with a stronger model in the analyst role scored worse — 3.99 against 3.55, losing the head-to-head 25–31. The cheap model stayed.

Corrections must earn their place

Finding that a company's guidance has been systematically optimistic is not a reason to correct for it — the pattern may be noise. Every candidate correction is replayed chronologically, estimating the bias from earlier periods only, and is applied only if it reduced walk-forward median error and improved a majority of periods. Two of seven candidates passed:

Company / metricnOutcome
HD comparable sales6Applied — walk-forward error 1.45 → 1.02pp, 67% of periods improved. Home Depot's comp guidance runs ~0.9pp optimistic.
ADI adjusted EPS6Applied — 0.17 → 0.04, 67% improved. ADI beats its own guide midpoint consistently.
ADI revenue, HD net sales5Withheld — only 2 walk-forward tests, need 3
HD adjusted EPS4Withheld — 1 test
Hays net fees, operating profit2Withheld — annual metric, no walk-forward tests available

The withheld five are visible in cache/calibration.json with the measured bias and the reason it was not used. A bias we can see but cannot validate is reported, not applied.

One correctness fix the backtest forced: bias was originally measured relative to the actual but applied multiplicatively to the estimate, which systematically under-corrects. Signed error is now measured in the space the correction acts in — relative to the estimate for money and EPS, in percentage points for percent metrics, where a relative error is meaningless for a series that crosses zero.

Caveat, stated plainly: for quarters reported before the models' training cutoffs the LLM-analyst route may have seen the actuals; quarters reported in 2026 are the cleanest window, and the two deterministic routes are contamination-free by construction.

Important design choices

  • LLMs transcribe and propose; arithmetic decides. Rejected alternative: "ask a strong model for the number with good context". It is unfalsifiable, unauditable, and its errors are invisible until the company reports.
  • Per-document extraction with caching. A fact depends only on its document, so the fact table time-slices for free — that is what makes the backtest nearly free and the final run fast and resumable.
  • No vector database. Rejected: embeddings over 1,139 files. The corpus is small, dated and structured; recency-plus-type selection and rg are transparent and reproducible.
  • Estimators abstain instead of guessing. Deere gives no quarterly EPS guidance — the guidance route abstains there and the median leans on the other routes, visibly in the audit trail.
  • Rejected: one autonomous agent per company. We built that too, as a baseline — spawn a sandboxed coding agent per company, have it research and return a schema-checked forecast. It works, and its twelve numbers land close to ours. But the schema can only check shape (units present, bear ≤ value ≤ bull, evidence IDs resolve); it cannot check that a cited number appears in the cited document, because the agent authors both the number and the evidence list. Its instruction to "state an arithmetic formula" is a request, not a constraint. We kept the constrained-role design because its guarantees are enforced rather than requested — and because a fresh agent per run cannot be re-run to the same answer.
  • External evidence is gated like internal evidence. A consensus anchor must be corroborated by two independent sources, dated no later than today, on the right basis, and not equal to a period the company has already reported. Uncorroborated numbers are recorded but never used.
  • Sample disagreement as a signal. Independent analyst samples answer the same prompt; a large spread flags the metric in validation. Planned as cross-provider Claude-vs-GPT, but only one provider's key was available on the day, so the spread is between independent samples of one model — and that model turns out to be highly self-consistent, which makes this check weaker than intended. Declared rather than dressed up.

Checks and tests

  • Quote-grounding gate on every extracted fact (number must appear in its verbatim quote; quote must appear in the document).
  • Unit traps handled explicitly: Hays EPS in pence, percentages as points (0.6 not 0.006), USDm magnitudes; the red-team pass may block only on unit/scale errors.
  • Magnitude bands vs prior-year values; absolute sanity bands (e.g. ADI gross margin 55–80%); conversion-ratio checks (Hays operating profit ÷ net fees; Deere PP&A profit ÷ total revenue).
  • Cross-metric consistency: HD net-sales growth vs comp sales within the new-stores/FX wedge.
  • 12 offline unit tests cover period math, estimator arithmetic, grounding, combination and the workbook writer: .venv/bin/python -m unittest discover -s tests.
  • Consensus-anchor gate: rejects future-dated figures (post-release leakage), company guidance sold as Street consensus, full-year figures quoted against a quarterly target, and values equal to an already-reported period; then requires two corroborating sources and takes their median. It earned its place — an early run anchored Home Depot adjusted EPS on a lone 4.87 that four independent providers contradicted at 4.62–4.73, and it had already moved our submitted number.
  • A failed validation blocks the workbook; the run log records every check with its outcome.

Known weaknesses

  • Extraction quality bounds everything: a guidance sentence the extractor misses is an estimate the ensemble never sees. The grounding gate stops hallucination, not omission.
  • The consensus anchor trusts public websites found during the event; a stale or wrong consensus shifts the final number by up to β of the gap. The snapshot is cited and timestamped so judges can inspect it.
  • Backtest sample sizes are small (≈4 quarters × 3 metrics per company) and partially contaminated for the LLM route (declared above).
  • Deere's segment metric (PP&A operating profit) has the thinnest guidance signal; we lean on seasonality and the analyst route there, and its answers varied the most between runs.

What actually went wrong today (and what it changed)

  • Our first extraction system prompt said the model must "never compute" — so it refused to convert $41.8bn to USD millions and returned zero facts. Mechanical unit conversion is now explicitly permitted; inventing numbers is not.
  • An early bug sent the extraction instructions without the document — the model correctly returned []. The cache key now hashes the full prompt so a prompt change can never serve stale results.
  • A newer 8-K's "an increase of $1.8 billion" was recorded as the quarter's level and, being newest, beat the correct 45,277 in the series. Fix: majority-vote clustering across every document that restates a figure — the truth appears many times, an extraction slip once.
  • The grounding gate rejected true facts for surprising reasons: Hays writes "pre -exceptional" with an OCR space, "£4 3.5m" with digits split, and tables get reconstructed rather than quoted. We added normalisation plus a fallback that accepts a fact only if all its numbers co-occur next to the metric's name in the document.
  • The red-team reviewer originally chose its own "blocking" severity and blocked ADI over a 0.2-in-6,784 rounding difference; it now only reports unit_error true/false, and only unit errors block.
  • We planned cross-provider ensembling (Claude vs GPT); only an OpenAI key was available on the day, so the disagreement check runs between independent gpt-5.1 samples instead.
  • rg's parallel file walk returned evidence in a different order on each run, which changed analyst prompts and made Deere's numbers wobble between runs — search output is now deterministically sorted.

Reproducing the final run

Requires Python 3.12, uv, Node (for the supplied checkers) and an OpenAI API key in .env (see .env.example). Secrets are never committed.

Two honest caveats about reproducing our exact figures. First, cache/calibration.json — the backtest-fitted weights and validated bias corrections — is committed deliberately, because the engine reads it and would otherwise silently fall back to untuned defaults and produce different numbers. Second, our reruns are bit-identical with a warm response cache; a clean clone re-calls the models, and model outputs are not guaranteed identical, so the analyst route can move a little. The deterministic routes, the arithmetic and every gate reproduce exactly.

uv venv .venv && uv pip install --python .venv/bin/python -r requirements.txt
