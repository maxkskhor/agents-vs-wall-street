Agents vs Wall Street

Glasshouse

A forecasting agent built on one rule: the language model is never allowed to say a forecast number. Models transcribe cited evidence and propose assumptions; deterministic arithmetic computes all twelve figures; a time-travel backtest — not taste — chooses how the estimates are combined.

Agent name: Glasshouse

Team: Team MYS — Max Khor, Yash Rai, Swareena Gurung

Build style and harness: A constrained-role pipeline, not an agent loop — no planner, no autonomous tool use, no multi-agent debate. The program calls models only for bounded, single-document jobs; all composition and arithmetic is ordinary code, and model output that fails a gate is discarded rather than negotiated with.

Models: One cheap OpenAI model in every role — transcription, analyst, red-team and consensus search. We tested a stronger model in the analyst role against the backtest and it scored worse, so it is not used. Exact model IDs are recorded in the entry form.

How it works

One command — .venv/bin/python -m agent run --all — runs the four companies in parallel through the same five stages, finishing in about 25 seconds. Every stage writes a JSON artifact under runs/<run-id>/, so each submitted cell can be traced offline from evidence to number.

The five stages

  1. Retrieve — newest results filings per company, picked by date and type. No embeddings; filenames carry the dates, which is what makes time-travel possible.
  2. Extract — a model copies out figures one document at a time, each with a verbatim quote. Gate: the quote must exist in the document and the number must exist in the quote.
  3. Estimate — three independent routes (below). Each abstains rather than guess.
  4. Combine — validated bias correction, then weighted median, then a shrink toward gated public consensus.
  5. Validate — deterministic gates block the workbook. The LLM reviewer only advises.

Research and financial reasoning

The scoring rule shaped the design. Accuracy is judged relative to Wall Street: |our miss| / max(WS miss, floor), capped at 5.0. Three consequences:

  • All four fiscal periods have already ended. We are predicting reported numbers for completed periods, so the freshest signals dominate: the latest guidance, and pre-announcements. Hays' 10 July trading update effectively pre-announces FY2026 net fees — the extractor treats it as a first-class pre-announcement fact that outranks older guidance.
  • Median beats mean. Under absolute-error scoring the optimal point forecast is the median of our belief distribution — hence weighted medians, never averages, everywhere in the engine.
  • Consensus is the benchmark, so know where it is. A cited, timestamped snapshot of public consensus (fetched by the models' web-search tools, cached to research/) anchors the final number; the ensemble moves us away from consensus only where extracted evidence pushes. If the network fails, the run proceeds un-anchored — the anchor is an input, not a dependency.

Conflicting evidence is resolved structurally rather than by vibes: later documents win for restatements; pre-announcements outrank guidance; adjusted-basis quotes are required for adjusted metrics; and quarterly figures are reconciled against full-year guidance through the catch-up arithmetic.

What the backtest measured

The corpus is frozen and dated, so the same pipeline can run "as of" the day before each past earnings report and be scored against the actual that later filings reveal. We report the floor-relative miss (our miss ÷ scoring floor, capped at 5.0) — the score we would receive if Wall Street were perfect, an upper bound on the real score.

The one to ask us about. The HD comparable-sales correction passed on six periods and we shipped a forecast of 0.27%. Extended to ten periods it stopped clearing the gate, and the number returned to 1.13% — near what guidance implies. The gate removed a correction we had already shipped. That is the whole argument for having one.

How much would the numbers move if we had chosen differently?

Caveat, stated plainly: for quarters reported before the models' training cutoffs the LLM-analyst route may have seen the actuals; quarters reported in 2026 are the cleanest window, and the two deterministic routes are contamination-free by construction.

Important design choices

  • LLMs transcribe and propose; arithmetic decides. Rejected alternative: "ask a strong model for the number with good context". It is unfalsifiable, unauditable, and its errors are invisible until the company reports.
  • Per-document extraction, cached. A fact depends only on its document, so the fact table time-slices for free — which is what makes the backtest cheap enough to run at all.
  • No vector database. Rejected: embeddings over 1,139 files. The corpus is small, dated and structured; recency-plus-type selection and rg are transparent and reproducible.
  • Estimators abstain instead of guessing. Deere gives no quarterly EPS guidance — the guidance route abstains there and the median leans on the other routes, visibly in the audit trail.
  • Rejected: an autonomous agent per company. A schema can check shape — units present, bear ≤ value ≤ bull, evidence IDs resolve — but not that a cited number appears in the cited document, because the agent authors both the number and the evidence list. "Show your arithmetic" is a request; ours is a constraint.
  • External evidence is gated like internal evidence. A consensus anchor needs two independent sources, dated no later than today, on the right basis, and not equal to an already-reported period. Uncorroborated numbers are recorded, never used.
  • The Street sometimes quotes a different metric. Six sources put Deere consensus "revenue" near 11.1bn. Ours is worldwide net sales and revenues; theirs is equipment operations. The Q2 filing states both — 13,369 against 11,778, a 0.878 ratio — so converted it implies ~12,630 and corroborates our forecast. Anchoring raw would have pulled us ~1,800 low.
  • Sample disagreement as a signal. Independent analyst samples answer the same prompt; a large spread flags the metric in validation. Planned as cross-provider Claude-vs-GPT, but only one provider's key was available on the day, so the spread is between independent samples of one model — and that model turns out to be highly self-consistent, which makes this check weaker than intended. Declared rather than dressed up.

Checks and tests

  • Quote-grounding gate on every extracted fact (number must appear in its verbatim quote; quote must appear in the document).
  • Unit traps handled explicitly: Hays EPS in pence, percentages as points (0.6 not 0.006), USDm magnitudes.
  • Magnitude bands vs prior-year values; absolute sanity bands (e.g. ADI gross margin 55–80%); conversion-ratio checks (Hays operating profit ÷ net fees; Deere PP&A profit ÷ total revenue).
  • Cross-metric consistency: HD net-sales growth vs comp sales within the new-stores/FX wedge.
  • 26 offline unit tests cover period math, estimator arithmetic, grounding, combination, the consensus gate and the workbook writer: .venv/bin/python -m unittest discover -s tests.
  • Consensus-anchor gate: rejects future-dated figures (post-release leakage), company guidance sold as Street consensus, full-year figures quoted against a quarterly target, and values equal to an already-reported period; then requires two corroborating sources and takes their median. It earned its place — an early run anchored Home Depot adjusted EPS on a lone 4.87 that four independent providers contradicted at 4.62–4.73, and it had already moved our submitted number.
  • A failed validation blocks the workbook; the run log records every check with its outcome.

Known weaknesses

  • Our third route is partly redundant with our first. Where guidance exists, the LLM analyst mostly re-derives it — on five of seven such metrics the two land within 0.4% of each other, because the model's adjustment is usually "apply the guidance midpoint", which the guidance route already computes deterministically. It earns its weight only where guidance abstains: all three Deere metrics and Hays EPS. That is also exactly where our sensitivity test shows the numbers move.
  • Extraction quality bounds everything: a guidance sentence the extractor misses is an estimate the ensemble never sees. The grounding gate stops hallucination, not omission.
  • The consensus anchor trusts public websites found during the event; a stale or wrong consensus shifts the final number by up to β of the gap. The snapshot is cited and timestamped so judges can inspect it.
  • Backtest samples are still small (10 reporting periods per company at most) and partially contaminated for the LLM route on pre-2026 quarters (declared above). Deeper history also spans structural breaks — Home Depot acquired SRS and GMS inside the window — so more data is not uniformly better data.
  • We tried to answer "is a bigger model a better analyst?" from the backtest. A first comparison favoured the cheap model, but at 31–25 on 56 rows that is p≈0.24 — indistinguishable from a coin toss, and we had initially reported it as a finding. It is not one. The cheap model is retained because it is cheaper and no worse, not because it was shown to be better.
  • Deere's segment metric (PP&A operating profit) has the thinnest guidance signal; we lean on seasonality and the analyst route there, and its answers varied the most between runs.

What went wrong, and what it changed

  • A newer 8-K's "an increase of $1.8 billion" was stored as the quarter's level and, being newest, beat the correct 45,277. Fix: majority-vote across every document restating a figure — the truth appears many times, a slip appears once.
  • The red-team reviewer blocked ADI over a 0.2-in-6,784 rounding difference, then blocked a correct 0.75pp comps figure. It is now advisory; deterministic gates decide.
  • rg's parallel file walk returned evidence in a different order each run, which changed analyst prompts and made Deere wobble. Search output is now deterministically sorted.
  • We reported the cheap model as a measurably better analyst on a 31–25 head-to-head. That is p≈0.24 — a coin toss. It is retained for being cheaper and no worse, not better.

Reproducing the final run

Requires Python 3.12, uv, Node (for the supplied checkers) and an OpenAI API key in .env (see .env.example). Secrets are never committed.

Two honest caveats about reproducing our exact figures. First, cache/calibration.json — the backtest-fitted weights and validated bias corrections — is committed deliberately, because the engine reads it and would otherwise silently fall back to untuned defaults and produce different numbers. Second, our reruns are bit-identical with a warm response cache; a clean clone re-calls the models, and model outputs are not guaranteed identical, so the analyst route can move a little. The deterministic routes, the arithmetic and every gate reproduce exactly.

uv venv .venv && uv pip install --python .venv/bin/python -r requirements.txt
